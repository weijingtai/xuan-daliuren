# 大六壬老架构 UI 深度诊断与重构指南

这份报告旨在对目前的大六壬“老架构”界面进行极其深入的、手术刀式的剖析。我们将从**视觉表象（UI）**深入到**用户体验（UX）**，最后落点于**响应式架构设计**的实施指南。

---

## 剖析第一层：全局视觉与布局的灾难 (Global Visual & Layout Issues)

### 1. 结构性失衡与“信息平铺”效应
目前的界面采用了最原始的**“数据 Dump”式布局**。即：后端返回了多少数据，前端就按垂直顺序原封不动地渲染出来。
*   **症状：** 全局缺乏核心聚焦点。排盘图本应是绝对的视觉中心，但下方密集的彩色神煞标签和成篇的古籍文字，其视觉重量（Visual Weight）完全盖过了排盘图本身。
*   **病因：** 缺乏“渐进式展开 (Progressive Disclosure)”的设计思维。在没有交互层级划分的情况下，将所有维度的分析结果（四柱、四课、三传、神煞、古籍）在同一平面内强制用户一次性接收。

### 2. 空间利用的极端低效 (响应式溃败)
*   **症状：** 在 PC 等宽屏设备上，界面依然呈现为单一的窄列瀑布流（或者强行拉伸满屏的单列）。
*   **病因：** 未引入网格系统 (Grid System) 和断点响应 (Breakpoints)。宽屏下，用户的眼球需要在极宽的屏幕两端来回扫视（尤其是阅读底部古籍时），这违背了网页排版中“最佳阅读行长（约 60-80 字符）”的原则。

### 3. 色彩与留白的窒息感
*   **色彩滥用：** 吉凶神煞的红绿色（如 `#FF0000`, `#00FF00` 级别的高饱和度）在浅色底上产生了强烈的“眩光效应”。
*   **边界线泛滥：** 界面中部（四柱、三传四课）使用了大量的实体黑色表格线。在现代 UI 设计中，实体线是阻断视线的最强元素，过多使用会导致界面极其沉闷（所谓“Excel 表格感”）。

## 剖析第二层：组件级深度诊断 (Component-Level Deep Dive)

我们需要将界面拆解，逐一审视：

### 1. 顶部状态卡片区 (Top Info Cards)
*   **现状：** 悬浮在最上方，投影生硬，与其他内容的关联性不强。字体偏小。
*   **改进方向：** 取消强烈的卡片投影。如果是基础信息（时间、节气），可以将其弱化为页面的 Header，而不是做成独立的卡片；或者将其整合进排盘图的边缘作为元数据展示。

### 2. 核心排盘图 (Core Astrolabe)
*   **现状：** 这是目前设计得最好的部分，有清晰的九宫格/十二地支方位。
*   **改进方向：** 需要进一步强化其“中枢”地位。未来可以加入交互：例如点击某个地支宫位，高亮对应的神煞。

### 3. 中部：四柱、四课、三传区
*   **现状：** 像一个缺乏设计的 HTML 基础 Table。天干地支没有视觉区分，五行属性没有通过色彩暗示。
*   **改进方向：**
    *   **去线化：** 移除所有内部表格边框，使用浅色背景块（如圆角小矩形）来包裹每一个天干/地支。
    *   **色彩暗示：** 可以隐晦地引入五行色（木绿、火红、土黄、金白、水黑）作为文字颜色的微调，但不宜过度饱和。

### 4. 灾难区：神煞群 (Shen Sha Cluster)
*   **现状：** 数以百计的彩色 Tag 堆砌，毫无分类逻辑，给用户造成极大的心理压迫感。
*   **改进方向（重构的核心难点）：**
    *   **维度分类：** 必须在 ViewModel 层对神煞进行数据分类（例如：按“年神/月神/日神”分类，或按“落在哪个地支宫位”分类）。
    *   **默认折叠：** 只展示最核心的几个大吉/大凶神煞，其余提供“展开全部”按钮。
    *   **Tag 视觉降级：** 放弃高饱和实心背景，改用**“浅色底 + 深色字 + 微边框”**的 Tag 样式（例如：背景 `rgba(255,0,0,0.1)`，文字 `#990000`）。

### 5. 底部：古籍释义区
*   **现状：** 纯文本长篇大论，没有段落间距，没有重点高亮。
*   **改进方向：** 引入富文本排版 (Typography)。增加行高 (`line-height: 1.6~1.8`)，增大段落间距。对关键的吉凶断语使用粗体或特定颜色进行高亮提取。

## 实施指南：响应式架构重构方案 (Responsive Refactoring Plan)

为了彻底解决“老架构”的布局死板问题，在 Flutter 代码重构时，建议遵循以下跨屏幕策略：

### 1. 布局范式转变：从 ListView 到 CustomScrollView (Slivers)
抛弃简单的 `Column` 或 `ListView`，改用 `CustomScrollView` 搭配各种 `Sliver` 组件。这能提供最强大的滚动性能和响应式网格布局能力。

### 2. 断点策略 (Breakpoints Design)

*   **Mobile (宽 < 600px)：单列沉浸模式**
    *   布局：依然是垂直单列，但严格执行“折叠”策略。神煞和古籍必须藏在 ExpansionPanel（手风琴）或者 TabBarView 里。
    *   核心：保证首屏 100% 被“顶部信息 + 排盘图”占据。

*   **Tablet (600px < 宽 < 1024px)：主次分栏模式**
    *   布局：尝试将屏幕分为上下或左右比例不均的区块。例如，顶部横向展示排盘图和四柱，下方采用网格 (`SliverGrid`) 来排列卡片化的古籍解析。

*   **Desktop/Web (宽 > 1024px)：专业双栏工作台模式 (Two-Column Dashboard)**
    *   **左栏 (主操作区, 固定宽度或按比例)：** 放置最核心的【排盘图】、【四柱四课三传】。这部分内容在宽屏下不应该被无限拉伸，以免变形。
    *   **右栏 (数据解析区, 弹性宽度)：** 放置【神煞解析】、【古籍详情】。这个区域可以通过一个侧边可滚动的 `ListView` 呈现，甚至在右栏内部做 Tab 切换。
    *   **最大容器宽度：** 使用 `ConstrainedBox`（如 `maxWidth: 1440`），保证在大屏幕上内容居中显示，两侧留白，不会因为屏幕过宽而撕裂布局。

### 3. UI 组件库的沉淀
在重构时，不要在业务页面里直接写颜色和边距。必须提取一套基础 Design System：
*   `DaliurenColors`：定义主色、文字主次色、背景色，以及特有的“吉/凶/平”语义色（低饱和度版）。
*   `DaliurenSpacing`：定义标准的间距规范（如 4px, 8px, 16px, 24px, 32px）。
*   `DaliurenTypography`：定义大标题、卡片标题、正文、说明文字的字号与行高。

### 结语
这次重构不仅仅是“换个好看的皮”，更是一场**信息降噪 (Information Denoising)** 运动。通过引入响应式分栏和渐进式展开，我们将把一个“机器 Dump 出来的数据日志”，变成一个“引导人类专家进行思考的数字化工作台”。
